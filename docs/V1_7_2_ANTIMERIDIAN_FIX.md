# v1.7.2 日期线插值修复

本分支是基于 `main` 的日期线算法补丁。CLI/GUI 中既有 v1.7.1 功能说明保持原样；本次没有制作新的安装包或正式 Release。

## 问题与修复

DEM 转换器已有跨日期线的 MDT 局部窗口与球面 IDW 检索，但 `DatumTransformer.get_delta_n()` 的栅格插值仍使用非周期边界。当查询位于最后一个像元中心与 +180° 之间时返回 NaN，导致对应 DEM 像元变为 NoData。EGM2008 起伏查询和直接 MDT 点位查询也有同类边界缺口。

本地 GOCO06s 差值栅格的首末经度中心为 −180° 和 179.975°，内部间距为 0.085°，接缝间距为 0.025°。直接使用数组的 `wrap` 模式不能表达这个实际间距，还可能将纬度一起循环。因此，修复保持原有内部双线性取值，只对经度超出中心范围的点处理周期接缝。根据实际首末中心和 360° 周期计算经向权重，纬向仍使用原有线性插值与边界限制。

GeoTIFF 只在地理坐标、无旋转、经度递增且接缝缺口不大于一个像元间距的近全球网格上启用此处理。直接 MDT 查询只对规则递增的全球经度网格启用周期处理。重复首末经度端点及 0–360° 布局有单独回归覆盖。

模型中声明的 NoData 在加载时转换为 NaN；内部真实缺测不会因接缝修复而被填充，接缝任一所需支撑点缺测时仍返回 NaN。地中海/黑海 EIGEN-6C4 选择规则、DEM 转换器的 MDT IDW 算法及默认 100 km 支撑距离没有改变。

## 历史结果与断点续算

批量转换的 `conversion_signature` 默认算法版本及实际调用均更新为 `1.7.2`。1.7.1 的历史指纹无法通过新算法的断点校验，因此会重新计算，而不会静默沿用含接缝缺口的旧产物。这是保守的全清单失效，不是只针对日期线瓦片失效。

代码修改本身不会扫描或重写既有 DEM 目录。若要使用新版本重新转换，建议先选择单独输出目录进行检查，避免覆盖人工修复、混合支撑距离或其他独立处理的成果。当前已补齐的全球 MSL 数据不需要因这次代码提交再跑一遍。

## 验证

`tests/test_v172_geoid_antimeridian.py` 包含 11 项测试，使用实际写入的合成 GeoTIFF/NetCDF，覆盖：

- 0.025° 非标准接缝间距、日期线两侧及等价经度；
- 标量、ΔN 经/纬度广播与纬度边界；
- 1000 个内部点与旧插值结果逐值一致；
- GOCO06s、EIGEN-6C4 与 EGM2008 取值入口；
- 模型 NoData、区域/投影/旋转栅格约束；
- 偏移经度中心、重复经度端点、直接 MDT 查询；
- 历史转换指纹失效。

在本地两个原始 DEM 上，用项目内修复后的转换器、默认 100 km MDT 支撑距离重新生成独立输出。对照此前已验证的独立补齐结果：

| 原始瓦片 | 原先因 ΔN 接缝缺失 | 原始有效像元 | 修复后有效像元 | 有效值最大差值 |
| --- | ---: | ---: | ---: | ---: |
| embedding_179E_65N.tif | 991 | 2689 | 2689 | 0 m |
| embedding_179E_70N.tif | 488 | 6065 | 6065 | 0 m |

两块瓦片均无剩余缺失或新增掩膜外有效值；原始 DEM、现有 MSL 成果及三份水准面模型的 SHA-256 保持一致。真实数据验证产物保留在本地，未上传模型或 DEM。

完整测试使用项目专属虚拟环境运行：

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
& '.\.venv\Scripts\python.exe' -B -m unittest discover -s tests -p 'test_*.py'
```

本地最终完整测试结果：347 项，全部通过。另在实际 CNES-CLS22、GOCO06s 差值和 EGM2008 模型上验证了赤道日期线两侧的点位：MDT 接缝结果与独立首末列插值一致，内部 MDT 值逐值不变，严格 EGM2008/WGS84 转换得到有限值。

这些验证证明边界插值、数据覆盖和数值一致性，不构成新的实测高程精度验证，也不改变 MDT 支撑距离所代表的科学限制。
